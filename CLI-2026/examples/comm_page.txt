# COMM page example session
#
# Demonstrates registering a parent-owned COMM page bound to a child
# domain's VP.  Multiple COMM pages per child are allowed.
#
# Replay with: load examples/comm_page.txt

# 1. Set up root domain with a memory region
init root 0x100000

# 2. Create a child domain and seal it
create-domain root child 0xf all
seal child

# 3. Carve a page from root's memory for the COMM buffer
carve r0 comm0 0x0 0x1000 rw

# 4. Register it bound to child VP 0 — monitor now maps [0x0, 0x1000)
#    Batch shows: 1 CommRegion update with target_domain_id and vp_id
register-comm comm0 child 0

# 5. Inspect: comm0 now carries COMM|CLEAN (not VITAL)
list

# 6. Register a second COMM page for VP 1 — multiple are allowed
carve r0 comm1 0x1000 0x1000 rw
register-comm comm1 child 1

# 7. Attempting to re-register a cap that already has COMM is rejected
# register-comm comm0 child 0   ← would fail: InvalidOperation

# 8. Attempting to carve, alias, or send a COMM cap is rejected
# carve comm0 bad_carve 0x0 0x100 r   ← would fail: PermissionDenied
# alias comm0 bad_alias 0x0 0x100 r   ← would fail: PermissionDenied

# 9. Revoking the COMM cap (from root) will:
#     - emit UncommRegion (monitor unmaps its access to the COMM page)
#     - emit ZeroMemory   (CLEAN: content wiped before returning to root)
#     - NOT emit RevokeDomain (COMM does not imply VITAL)
revoke r0 comm0
