# Tutorial 7: Nested Enclave Architecture
# ========================================
# Demonstrates creating a CVM with a nested secure enclave inside.

@msg ━━━ Tutorial 7: Nested Enclave (CVM → Enclave) ━━━
@msg
@msg This tutorial demonstrates a three-level hierarchy:
@msg   Hypervisor → CVM → Secure Enclave
@msg Each level has decreasing visibility but increasing security.
@msg

# Initialize
@msg 📋 Step 1: Initialize hypervisor
init hypervisor 0x80000000

@msg
@msg ✓ Hypervisor with 2GB memory pool
@msg

# Create CVM
@msg 📋 Step 2: Create a Confidential VM
create-domain hypervisor cvm1 0b1111 GET,ATTEST,SWITCH,SEAL,CARVE

@msg
@msg ✓ CVM created with permissions to create child domains
@msg   Note: SEAL and CARVE permissions allow CVM to create enclaves
@msg

# Allocate memory for CVM
@msg 📋 Step 3: Carve large private memory for CVM (512MB)
carve r0 cvm1_mem 0x10000000 0x20000000 RWX

@msg
@msg ✓ CVM has 512MB private memory
@msg

# Send memory to CVM
@msg 📋 Step 4: Send memory to CVM
send cvm1_mem cvm1

@msg
@msg ✓ CVM owns its memory region
@msg

# Create shared buffer between hypervisor and CVM
@msg 📋 Step 5: Create shared I/O buffer for hypervisor-CVM communication
alias r0 hv_cvm_shared 0x1000000 0x10000 RW
send hv_cvm_shared cvm1

@msg
@msg ✓ Hypervisor and CVM share I/O buffer
@msg

# Now create an enclave inside the CVM
@msg 📋 Step 6: CVM creates a secure enclave (nested domain)
create-domain cvm1 enclave1 0b0011 GET,ATTEST

@msg
@msg ✓ Enclave created inside CVM
@msg   Hierarchy: hypervisor → cvm1 → enclave1
@msg

# CVM carves memory for the enclave
@msg 📋 Step 7: CVM carves exclusive memory for enclave (16MB)
carve cvm1_mem enclave_private 0x10000000 0x1000000 RWX

@msg
@msg ✓ Enclave has 16MB private memory
@msg   CVM can no longer access this region!
@msg

# CVM creates shared buffer with enclave
@msg 📋 Step 8: CVM creates shared buffer for enclave communication
alias cvm1_mem enclave_shared 0x11000000 0x10000 RW

@msg
@msg ✓ CVM and enclave share a communication buffer
@msg

# Send memory to enclave
@msg 📋 Step 9: Send memory capabilities to enclave
send enclave_private enclave1
send enclave_shared enclave1

@msg
@msg ✓ Enclave has both private and shared memory
@msg

# Seal everything
@msg 📋 Step 10: Seal all domains
seal cvm1
seal enclave1

@msg
@msg ✓ All domains sealed
@msg

# Attest the enclave
@msg 📋 Step 11: Attest the enclave (most sensitive component)
attest enclave1

@msg
@msg ✓ Enclave attestation shows:
@msg   • Private memory (invisible to CVM and hypervisor)
@msg   • Shared buffer with CVM only
@msg   • Parent is CVM, not hypervisor
@msg

# View all domains
@msg 📋 Step 12: View complete hierarchy
list

@msg
@msg 📖 Key Takeaways:
@msg   • Nested domains create hierarchical trust boundaries
@msg   • Each level can create children with SEAL+CARVE permissions
@msg   • Enclave memory is invisible to parent CVM
@msg   • Shared buffers enable controlled communication
@msg   • Attestation proves the enclave's isolation
@msg
@msg 💡 Architecture Pattern:
@msg   ┌────────────────┐
@msg   │  Hypervisor    │ ← Access: HV memory + hv_cvm_shared
@msg   └────────┬───────┘
@msg            │ creates
@msg   ┌────────▼───────┐
@msg   │      CVM       │ ← Access: CVM memory + shared buffers
@msg   └────────┬───────┘   (NOT enclave private memory)
@msg            │ creates
@msg   ┌────────▼───────┐
@msg   │    Enclave     │ ← Access: Enclave private + enclave_shared
@msg   └────────────────┘   (Highest security)
@msg
@msg   Data Flow: Hypervisor ↔ CVM ↔ Enclave
@msg   Visibility: Hypervisor > CVM > Enclave (decreasing)
@msg   Security: Enclave > CVM > Hypervisor (increasing)
@msg
